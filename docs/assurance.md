The audit covers 21,691 declarations, including 9,818 theorems and generated ones, and gate tests require it to reject every forbidden construct, axiom and lookalike.

nanoda, an independent Lean kernel in Rust, re-checks every declaration from `lean4export`'s export and admits only the three allowed axioms, so a wrong proof would have to pass both kernels.

The source gate (`scripts/SourceGate.lean`) parses every module before elaboration and allow-lists commands, attributes, options and imports for Lean 4.30.0; it is a tripwire, so CI builds without secrets or network. The proofs are re-checked on fresh machines of their own, from the archive the build names by its digest.

A green `checks` run certifies the change with its own scripts; `.github/workflows/verify.yml`, taken from the default branch, reports whether every required job passed and whether the change edits its checks, which a branch rule must require to block a merge.

A job's pass recorded by a run of this repository's branches lets a run on the same inputs skip it (`scripts/prior_pass.py`): such runs are trusted as the writers are, a fork's never, and a pass counts only where GitHub says the step recording it passed.

The checks' stamps are made by the code they run, so a branch takes up only its own and the default branch's.

## Open proof connections

1. **Semantics correspondence.** `DN.Compiler.Semantics` is a transcription of HOL4's, compared clause by clause in [pancake-semantics](pancake-semantics.md) and run against HOL's `evaluate` on the state corpus, not a certified translation.

2. **Source representation.** The programs `dn-compiler` prints, 241 in all, are each read by the pinned parser as its lowering in canonical form, which `Canon.canon_eval` proves keeps evaluation. `printed_well` relies on 62 of that table's 320 cells; the parser's theorem is open, and the differential suite runs 35,520 cases.

3. **Backend identity.** CI uses the pinned release with `--reg_alg=0`, whose theorem holds for every allocator. The patched source's proof rebuilds without oracle and its bootstrapped compiler passes the native lanes, both reading each of the 241 programs the same way, but no theorem covers the binary.

4. **Shift distances.** `Checked.emit` takes only a literal distance below 64, since the release accepts larger ones the semantics gives no value.

5. **Native ABI and memory.** The export returns 32 bits to C, so full words go through `Abi.wordResult`'s output slots. In the model a run that does not fail ends the same rewritten, the slot in the memory domain (`DN.Compiler.Preservation`); a C host's slot is outside it (item 8). Heap and stack sizes are tested, not proven.

6. **Host refinement.** No theorem connects the Rust primitives or the hosts to the Lean dataplane models, whose statements are about the models.

7. **Entry points.** CakeML's theorem covers `main` only, so the server runs inside `main` and reaches its host through external calls ([decision 0002](decisions/0002-entry-and-memory.md)); the exported kernels are tests outside the theorem.

8. **Addresses the theorem admits.** The theorem's memory is CakeML's heap, so every buffer lives there, the hosts write and check the heap header it fixes, and the analysis keeps off the heap's first 64 bytes. The stack bound (`max_depth`) is not yet obtained; for every other run here, whose buffers the C host owns, the premise is false.

9. **Protocol and persistence.** Decision 0005's store is specified and proven above, and its recovery runs in the session's `main`. The session with POST and reading by message-id is specified, in the program, and tested, not proven.

## Reproducibility boundaries

`tools.lock.json` pins every tool archive and source by digest, built outside the checkout and checked against a manifest on every use; this is not a hermetic build of system dependencies, and benchmarks are not news-server throughput.
