# Compiler baseline

The compiler has a useful, executable core: real code generation, a documented C ABI, and a small TCP service. The inherited workloads whose names suggested more integration than existed have been removed (see below); what is left is the emitted subset, its proofs and the dataplane models.

The follow-up [four-reviewer audit and triage](reviews/README.md) fixes a nested-load printer bug and CI failure-propagation hole, and identifies concrete inherited contracts and lifecycle gaps. Read it before extending or porting the preserved modules; the inherited compiler workloads it discusses were removed afterwards.

## Reproduce the baseline

On Linux x86-64, install the prerequisites from the root README, then run:

```sh
bash scripts/check_all.sh
```

This command fails if any required lane fails, and does not skip native tests on unsupported hosts. `bash scripts/check.sh` is the model/host baseline without the native lanes, and `bash scripts/lint.sh` the static checks. The native lanes are listed once, in `scripts/native_lanes.sh`, which `check_all.sh` and CI both run; given names (`bash scripts/native_lanes.sh parser`), it runs only those. CI runs them as one chain (lint, build without network, proofs on a fresh machine, tests) in one checkout and uploads source, assembly, logs and JSON reports; since a lane there could lean on what an earlier one left in `build/`, the nightly run also starts each lane alone on a fresh machine. Each native lane writes `build/<lane>/report.json` (`native`, `baseline`, `entry`, `server`, `framing`, `session`, `nntp`, `parser`, `fuzz`) with the same header: the platform, the digests of the Pancake compiler, of `dn-compiler` when it printed what was checked and of the host sources, and how long the run took. A lane removes its last report before it starts, so a failed rerun leaves none, and a lane that refuses says why in one line starting with `DN`.

The generated lane also runs larger: `python3 scripts/native_fuzz.py --cake "$(python3 scripts/bootstrap_tool.py cake)" --seed N --count C --vectors V` draws `C` programs with `V` inputs each from seed `N`, without the planted defects and recorded cases of the standard run. The nightly run draws 5,000 programs with 8 inputs each from a seed taken from the date; its summary gives the seed and two ways to repeat it: the same command, or the nightly workflow run by hand with `seed`, `count` and `vectors`. A disagreement it found is reduced to `build/fuzz/minimized/`, kept as the `generated-programs` artifact. `--bootstrapped` runs the lane with the compiler built from the patched source.

The default native compiler is the digest-pinned release in `tools.lock.json`. Setting `CAKE` deliberately selects a different compiler, whose digest is recorded; the compiler `scripts/bootstrap_cake.sh` builds from the patched source is one ([backend](../backend/README.md#bootstrap-the-compiler)). A run with one compiler says nothing about the other.

### Generated programs

300 generated programs, 1,200 calls, drawn from a fixed seed by `DN.Compiler.Gen`, each program allowed a different mix of constructs (swarm testing). Among what the calls reach: word and byte loads nested in each other's addresses in all four pairings, word and byte stores, branches both ways, loop iterations, declarations in inner blocks, returns from branches and loops, pointers loaded from a page of pointers the host fills with real addresses, pointer locals, addresses computed from data, a byte reached through two pointers and stored to, and the first and last byte and word of each of the three buffers; some program declares a name again in a sibling block, and some takes each of zero to three parameters.

Each program goes through the gate and the printer; on every call the model, an independent interpreter of the source (`scripts/fuzz_interp.py`) and the compiled code must return the same word and change the same words of memory, with each buffer between pages without access, the page of pointers read-only, the rest of the result slot's page untouched and a tenth of a second per call; the host is first shown to report a call that hangs, one that reads past its buffer and one that writes beside the slot; the parser contract holds every program; and the run fails if any construct above is reached by no call.

A disagreement of any of the three is reduced to a small case in `build/fuzz/minimized/`. The standard run takes well under a minute, the nightly one (5,000 programs, above) a few minutes; both sizes are chosen, not derived.

Bounded random sampling, not a theorem. The generator emits only accesses inside the buffers, since the compiler theorem covers no program that faults, and only addresses CakeML's static checker trusts; it emits no calls, which the gate refuses.

### Printed source against the parser

152 printed programs — kernels, the source-language example, the server's loop, the framers, the session's program, the gate's accepted examples and every differential fixture — which together use every statement and expression form the gate accepts, each read by the pinned parser (`cake --explore`) as exactly its lowering in canonical form, with no function besides; and 208 cells of the precedence table, each read by the parser as the table says, both ways, of which `printed_well` relies on 46. A regrouped subtraction, a bare nested load, a function nobody printed and the table with one cell turned either way are refused.

Checked against the release on every run, and against the bootstrapped compiler as well by `scripts/parser_contract.py --bootstrapped`, which first checks its digest against `backend/bootstrap-record.json`.

The correspondence is checked program by program, not proved; the canonical form is proved to keep evaluation (`Canon.canon_eval`).

### Reply table

5,790 calls of `dn_reply`, ten for each of 579 inputs — every prefix of each keyword, each keyword followed by more bytes or with one byte changed at each position, all 256 single bytes and scattered inputs, one keyword made of bytes above `0x7f` and a NUL so that a byte load extending the sign would show — checked against the replies the Lean program computes, which an independent Python reference checks in turn; the reference checks that the inputs still reach those cases.

Each input is called with a buffer of exactly the room the program asks for, a larger one, one byte too small, and each length negative, where nothing may be written; each call is made with both buffers against a page without access after them and again before them, with the input read-only and the fill changed between the two.

Every program the emitter accepts is proven, in the model, to produce its reply and change nothing else (`DN.Dsl.Correct`); the printed source, the CakeML compiler and the host are tested here, not proven. The pages without access check the machine code the compiler produced, which leaves out loads whose value is never used. A negative capacity is also below the program's own bound, so no call tells its separate check from that one.

### Entry designs

The reply table built into both ways of entering generated code (`scripts/entry_bench.py check`): exported functions called by C, and a loop in the program's `main` that fetches requests through external calls into its own heap. Every reply in both is compared with the independent reference; the program writes nothing in its heap outside its batch areas; the heap header the host writes is the one the compiler theorem requires, recomputed from the assembly and the linked symbols; every array the program hands the host lies in the heap; and a host that sends more events than a batch holds, a negative count, or a length past its slot or negative, stops the program. Four servers answer eight connections over loopback.

The loop is Pancake written by hand, since the emitter does not take calls or external calls yet, and it is built with `--main_return` so that the benchmark can end, which the server of decision 0002 is not; the servers take one read for one request and send while blocking, which a benchmark client allows and real clients would not. `measure` produces the figures in [decision 0002](decisions/0002-entry-and-memory.md) and does not run in CI.

### Server loop

`scripts/server_check.py` runs the server's loop as its host would. The gate prints it as a whole program — a `main` without parameters that reaches its host through the external calls `dn_next` and `dn_emit` — built without `--main_return`, so the start-up code gives it no way back to the host. Its layout comes from `DN.Server.Layout`, which `dn-compiler emit-layout` prints as a C header. The host (`native/skeleton_check.c`) hands it four scripted batches — one with events of every other kind, which the loop has to leave alone, a full one of sixteen and an empty one — and requires every received payload back, in order, as a send to the same connection that reads on. On every call the heap header has to be intact, the heap outside the layout untouched, and each array the program hands over exactly its area of the layout; the host then ends the run inside a call, as a server host does. Four hostile batches — a count of events or a length just below zero or just above its bound — have to end the run, and a run whose heap header was never written is refused on its first call. The checking host fills the heap and the stack before the run and reads them during it; the program's theorem holds for any initial content, and a serving host does neither.

In the model, `DN.Server.SkeletonSafe.never_fails` proves that no run of the loop fails, for every host, every clock and every content of the heap, given that the heap covers the layout above its header, which a heap of just the layout's words from an aligned base does (`covers_witness`); `printed_never_fails` ties it to the text the gate prints, whose reading back by the parser is checked, not proved. As for the session's program, the safety analysis of [decision 0004](decisions/0004-safety-analysis.md) accepts the loop and the kernel runs it; so that intervals see every action fit its batch, the loop also checks the count of actions against the batch and returns 3 past it, which the count of events already rules out. The report records how deep the loop's frames reach from the top of the 1 MiB stack the host provisions and how much of the stack's bottom the start-up code uses for CakeML's store, both measured on the script's run; the bound CakeML's theorem asks for is computed in HOL (`max_depth`, `pancake/proofs/pan_to_targetProofScript.sml`), which the compiler does not print, and is not yet obtained.

### Framers

`scripts/framing_check.py` holds the framers three ways. `dn-compiler frame-model` runs them as the Lean model does, which `DN.News.FramerCode` proves the printed programs to follow step for step and `DN.News.Framer` proves equal to the specification in `DN.News.FrameSpec`: a stream is its lines, each ended by an LF, and a command is a line with a CR right before its LF and nowhere else, no NUL, and at most 512 octets with its line end; a block ends at the first line that is a single dot, and is refused when a line holds a CR, an LF or a NUL. `scripts/framing_ref.py` computes the same answers over the whole stream at once, cutting it with `split` and finding the end of each block as a substring, with no state carried between chunks. `native/framing_driver.c` feeds the compiled code a chunk at a time, each call from where the last one stopped, and after a block ends starts the next from the state it left; a call that reports nothing has to have read the whole chunk, and one that reports a line or a block has to have stopped right after its LF. Each chunk lies at the end of its page, read-only while the framer runs, and the framer's state as near the end of its page as its alignment allows, both next to a page without access; the rest of the state's page is checked after every call. Each framer first has to refuse a negative count, a negative position and a position past the count without reading its input, which lies on a page without access, or touching its state's page. The code run is that of the exported functions, not the same statements compiled inside a session's `main`. The cases: every string of up to six bytes over CR, LF, ".", NUL, space and "A", whole and cut in two at every point, for lines of at most four octets and blocks of at most four bytes, so that every limit is within reach; for the session's sizes, lines of 512 octets and blocks of 64 bytes, the same strings of up to three and five bytes, alone and after a line or a block at its limit or up to three bytes short of it; variants of the end-of-data sequences of SMTP smuggling (2023) inside a block, each cut every way, which must not end it; lines ended by a bare CR or LF; lines of 510 to 514 octets with their line end, and of 1,537; a block's end cut every way; blocks at their buffer's size and one byte either side; each vector also fed a byte at a time. The model counts which way through each of the four programs every byte takes, and each has to be taken at least three times in each program.

### Header field grammar

`scripts/abnf_check.py` holds the grammar the header checks rest on. `scripts/gen_abnf.py` takes each rule from an RFC's text in `rfcs/` and writes the grammar twice, as ABNF (`scripts/netnews.abnf`) and as Lean data (`DN.News.AbnfRules`); a difference from what it would write, or a rule that does not read back as itself, fails the lane. Where it departs from an RFC's text it says why: the verified errata that change a rule (RFC 5322's 6639 and 3979, RFC 2045's 512, RFC 2231's 477 and 7326, RFC 5234's 2968 and 3076, RFC 5536's 5116), which the upstream check keeps verified; RFC 5322 §4's obsolete syntax taken out but for the phrase and the "GMT" zone RFC 5536 §2.1 keeps, while RFC 8315's obsolete scheme and key stay; RFC 5536's own versions of RFC 5322's rules; the space after the colon RFC 5536 §2.2 asks of every field, added to RFC 5322's fields and `optional-field`; RFC 2045's and RFC 2231's `token` and `parameter`, carried over by hand from RFC 822's notation with the comments and white space it allows around "=" (RFC 5536 §3.2.8), and the characters a token and an attribute may not hold read from the RFCs' text; RFC 5536 §3.2.4's `dist-name`, grouped as its text intends, since its ABNF admits no name of more than one character starting with a letter; RFC 5322's `path` renamed, since RFC 5536 gives the name to the Path field. A table names each field's rule and section; a field of another name is an `optional-field` with RFC 5536's `unstructured`. RFC 5536 §3.1.3's `msg-id`, without the comments and white space RFC 5322's carries around it, applies wherever one is used; References, as RFC 5536 §3.2.10 has it, and In-Reply-To and Resent-Message-ID, which it does not restate, get them in their own rules, where RFC 5322's `msg-id` had them. MIME's fields are optional fields: RFC 5536 §3.2 gives them RFC 2045's meanings under the rules of §2.2, and the server, which does not read MIME structure, checks them by those rules alone. The generator refuses a left-recursive grammar and counts the most terms a match goes through at one position, 36 for this grammar. The rules are IETF Code Components; both files carry the attribution and notices the IETF Trust's Legal Provisions and RFC 2231 ask for.

`DN.News.Abnf` runs a grammar as a chart parser does: what a rule matches from a position is the set of positions a match can end at, worked out once per rule and position. Each nested term takes a unit of fuel, and a run gets the count above for each position of its input, which `DN.News.Abnf` shows to be enough; running out, or a rule the grammar lacks, gives an answer of its own that no case may get. `dn-compiler abnf-model` answers cases with it; the reference is the `abnf` library 2.9.0 with its Rust backend, pinned by digest in `scripts/requirements-tests.txt`, with its own parser and core rules; a case the Rust backend stops on, near 180 rules deep, is decided by its pure-Python backend on a large stack. The cases: forty derivations by abnfgen 0.21 (built from its pinned source, a third reading of ABNF, one run each) for each field's rule and seventeen rules inside them; two derivations of every rule for each choice of each alternation; each changed where a field line's rules are — no space after the colon or no line end, a bare LF or a space before it — and at four places drawn from a fixed seed, a byte dropped, replaced or inserted, and at two, a letter, a digit or a sign that ends a run of them written twice and three times, which can take a run past its upper bound; an IPv4 and an IPv6 address one past a bound that no change makes; comments nested 500 deep; and 107 examples the RFCs print. On the 49,838 cases the two agree, and every field's rule is seen to accept and to refuse. ### Journal

### Session model

`scripts/session_check.py` holds the session of decision 0003 against an independent reference before any program runs it. `DN.News.CommandSpec` says which reply each line gets, from RFC 3977's grammar and the order of checks 0003 fixes, and shows each of its rules to matter with a version that breaks it; `DN.News.SessionSpec` is the session as a function of what the host reports — a table of sixty-four connections and the host's clock, a turn that takes a batch of events to at most one action a connection, what the host took of each send, and when the next turn is due — and proves what a turn guarantees ([assurance](assurance.md)). `dn-compiler session-model` runs it a line at a time. The lane's host simulator does what 0003 asks of the host: the lowest free index and its next generation, no new connection while every index is in use, reading only while the last action asked to and everything it carried was taken, one input a connection a batch, and at most 512 bytes of it, readiness once the client takes more, the end of input once the client's bytes are read, the connections taken in turn when more than a batch has news, the next turn when asked or at once when anything waits. Its scenarios include every kind of event of a connection gone (input, readiness, the end of input and its close) while its index is free and again once the index serves another, a client reported ready that takes nothing, a clock from zero, the longest and the shortest identity that fit the replies, and 300 clients drawn at random from a fixed seed, sending pieces of lines after gaps on and around the deadlines, now and then reading slowly, pausing, ending their input or reset. `scripts/session_ref.py` judges every turn from outside: from the bytes each connection sent, split at LF and classified by the framing reference, it computes the greeting and the replies the client should get, in order, up to the reply to QUIT, and from the times things happened the three deadlines — the first command, inactivity with no command answered and no output taken, and the rest of a line from when the program waits for it, again from when a line is answered. It refuses a send that is not the next whole reply or the rest of an untaken one, or that comes before the host reported the connection ready; a request to read, or not to, that does not match whether every whole line is answered; a connection not greeted in the turn it opens, one not reading with nothing to answer, one left with output to send again; a close no deadline justifies, and a deadline passed without one; a graceful close before the output is taken or with lines unanswered; and a next turn that is not at once when a connection can go on, or else exactly at the earliest deadline. Eleven hosts that break the contract (listed in `scripts/session_check.py`) each end the run with their code.

### Session program

`scripts/session_native.py` holds the compiled session against its model. `DN.Server.Session` writes the session as one Pancake `main` that loops over the two calls of decision 0003. Its layout (`DN.Server.SessionLayout`) — the two calls' arrays, down to the fields of an event and an action, and the program's own area with its copy of the identity, the texts of the replies and a table of sixty-four connection records — reaches the host as a C header (`dn-compiler emit-session-layout`); its sizes are the specification's, by definition or by a theorem (`sizes_agree`, `identity_ok`), and it fits the heap segment the host provisions (`size_fits`). The command-line framer inside it is the statements of `DN.News.FramerProg` that `DN.News.FramerCode` proves in the exported framer, printed in place; that they frame the same inside the session is tested with the session, not proven. Of what the host writes back into an action, the program reads only how many bytes were taken; the rest it knows from its own records. CakeML compiles the printed program without `--main_return`, and `native/session_host.c` runs it speaking the line protocol of `dn-compiler session-model`, so the lane's simulated host drives the compiled code exactly as it drives the model. On every scenario of the session model's lane the two traces — every batch, every action, what the host took and every next turn — have to be equal, and so do the whole answers of the model and the compiled code to the eleven hosts that break the contract (ten reach the program: a count for no send cannot be written in the layout, so the host answers it itself, as the model does), to six scripts at the edges of what it allows, and to 200 hosts drawn at random from a fixed seed, each for up to sixty turns, which mostly keep the contract as far as they can tell and now and then break it. Twenty more hosts break the contract in ways the model's protocol cannot say — an identity that does not fit, events of unknown kinds, and ten that write into the program's own area a word it reads back as a length or a position, one for each place it checks such a word — and have to stop the compiled code with codes 9, 8 and 10. The code a run stops with is read from the program's area when the runtime ends the run. The host fills the heap past its header before the run and checks, on every call and when the run ends, the heap header and the heap before the program's first area and past its layout, and on every call that each array is its area of the layout, that the count of actions is the number of slots that hold one, each for its own connection, and that a send's word to read is 0 or 1. Thirty defects planted in the printed program (listed in `scripts/session_native.py`) each have to be caught, and caught the way they name: by a turn that differs, a stop on a host that kept the contract, a missing stop code, an edge, or the host's own check.

In the model, `DN.Server.SessionSafe.never_fails` proves that no run of the program fails, for every host, every clock and every content of the heap, given that the heap covers the layout above its header (`covers_witness`); `printed_never_fails` ties it to the text the gate prints. It is not proven by hand: the safety analysis of [decision 0004](decisions/0004-safety-analysis.md) accepts the program, the kernel runs the analysis on it (about 40 s and 7.4 GB of memory in the build, which prints its time and largest process on every run), and `DN.Compiler.AnalyzerSound` proves once that a program the analysis accepts never errs. The analysis refuses any access to the heap's first 64 bytes, so a run from a heap without the header's words never fails either, and never reaches them; that a run from the heap with them is the same run is not proven, and the host checks the header on every call. Sixteen examples in `DN.Compiler.Analyzer` show what the analysis accepts and refuses. The analysis needs the program to check each word it reads back from its own area and uses as a length or a position; the lane reaches each of those checks, by a host that writes into that area.

### NNTP server

`scripts/nntp_check.py` runs the server: the session's program with its host, `native/nntp_host.c`, which knows sockets and the clock and nothing of the protocol. It listens on the address it is given, IPv4 or IPv6, and sets `TCP_NODELAY` on every connection, so that a reply leaves as soon as the program hands it over. The host polls with `poll` and gives out what one poll reported before polling again — the connections taken in turn, at most a batch of events, input read straight into the event's slot and only from a connection that asked for it and has nothing untaken, new connections only while an index is free — and carries out each action for the connection's current generation, writing back what the kernel took of each send. The end of input is a read of nothing; a reset, a failed read or send, or a hang-up is a close, reported in the next turn; a graceful close shuts down sending and reads and drops what still comes until the client closes its side, for 30 s at most and 5 s of silence, outside the table, the one that has lingered longest closed when sixty-four already linger. An accept that runs out of descriptors or memory leaves the listener alone for 100 ms. Every action is checked against the layout. SIGTERM, read through `signalfd` in the same poll, closes every socket and ends the run inside a call. For the checks, the host takes its time from a descriptor the check writes to, so that time moves only then, and reports each turn on another — the time handed to the program, its events with the bytes received and the port of each new client, its actions with their bytes, what the kernel took of each send, and the time the program asked to be woken at or its code if it stopped the run — which the check reads as it comes, never sleeping to wait for a turn. The report of every run but `nntplib`'s, which runs the server as in use, is held three times when the run ends: `session_ref.judge` holds the program to the session's contract; the model, `dn-compiler session-model`, replays it: given each turn's time, events and what the kernel took, it has to act and ask to be woken as the program did; and it is held against the clients' sockets and the host's side of the contract — what a client sent reaches its input in order, all of it once the input ends; what it read is what the kernel took of the program's sends; input comes only from a connection whose last send asked to read and was taken whole, at most once a batch; `writable` only after a send taken in part; no event after a close, no batch past its size, no index given out again with a generation it had. No turn is taken with nothing to do: a turn has events, unless the one before filled its batch or the time it asked for has come; and while a check waits with nothing happening, the server spends less than a quarter of that time on the processor. Whether the server still holds a socket, and how many descriptors it holds, is read off the kernel's tables in `/proc`, not asked of the server.

The standard library's `nntplib` is greeted, reads the capabilities and the help, and quits, and the replies it parses are `session_ref`'s texts. A pipeline — the recorded transcripts of commands, without its QUIT, and of long lines, then a HELP after the QUIT that ends them — gets every reply the slice has, in order, the connection closing at that QUIT. Three transcripts recorded in `tests/golden/nntp-transcripts.json` — commands, long lines, and lines after a QUIT — each hold what a client sends and what it has to read, which `session_ref` has to compute too; each is sent cut at every position into two parts, the second once the host has given the program the first, 1,831 cuts in all, and one is sent a byte at a time; each client reads what its transcript records. A client that shuts down its sending side gets the replies to its whole lines and then the end, reported as the end of input, not a close; a reset mid-line is reported as a close, and the next client is served. A client that reads nothing until its receive queue stops growing gets every byte once it reads; a client that reads nothing and sends a line at a time has its next line wait in the kernel once the answer that asks to read again is taken only in part; one reset while a send waits for room is reported closed and never ready to write, and the next client is served. On a clock the check moves, the deadlines of the first command, of a line and of inactivity close their connections at the time the program asked to be woken at, not a millisecond before, and at once: the server no longer holds the socket. A client that sends QUIT and a line after it reads the reply and the end; the server holds its socket until the client closes its side, after which it closes it and does nothing more, or until 5 s of silence, or while the client keeps sending until 30 s in all, and not a millisecond before. With its limit on descriptors lowered to those it holds, the server takes one turn on the refused accept, logs the pause once, serves nothing for 99 ms and serves the waiting client at 100. On the real clock, the first command's deadline closes between 9.99 and 11 seconds after the client connects; a client that quits and stays silent has its socket held at 4.5 s and closed by 6 s; the server uses less than 0.2 s of processor time over all of it; and a client refused for want of descriptors is served, by the host's clock, between 100 ms and 1 s after the turn that refused it, with nothing else to wake the server. A hundred clients reset one after another leave the server the descriptors it had; of seventy that quit and keep their side open it keeps the last sixty-four, and sixty-four descriptors more. Sixty-four clients connecting while the server is stopped are taken sixteen a batch; the sixty-fifth gets nothing while they are served and is greeted once one closes; one reset while it waits is closed in the turn the server takes it. A program changed to act for the generation before its connection's has none of its actions carried out: the host reports nothing of its sends taken, and the client reads nothing. A client over IPv6 is greeted and answered. Each run ends on SIGTERM with status 0.

The check has to catch 40 planted defects (listed in `scripts/nntp_check.py`), each by the check named for it and for the reason named. Not planted, since nothing outside could tell: a batch that does not rotate where it starts and a failed send not marked lost — the host gives out all one poll reported before it polls again, so a connection one batch does not reach the next one does, and a socket whose send failed hangs up at the next poll; nor `TCP_NODELAY` left off, which only delays a reply until the one before it is acknowledged: on loopback no check can time that reliably, and no portable call reads another process's socket option.

### Test sensitivity

- A separately compiled copy kernel with its store removed must fail the real copy test, and so must three that break the capacity contract the host relies on, each for its reason: no bound on the capacity, the bound one too high, and the whole capacity copied.
- Five defects planted in the printer — `<=` printed as `<`, a byte store as a word store, a byte load as a word load, the condition of an `if` negated, a shift distance one off — must each fail the generated lane; the program that shows each is reduced (`scripts/fuzz_reduce.py`) to the case recorded in `tests/corpus/mutants/`, which `DN.Compiler.GenCorpus` holds as a regression too; every run reduces again the program each case was reduced from and must arrive at the same case.
- Six reply kernels, each breaking one thing the reply check claims, must fail it: a reply byte not written, the right bytes with the wrong length, a byte written past the reply, a byte written into the input (which faults, the input being read-only), a buffer one byte too small accepted, and a keyword compared without the length guard (which faults on the page after the input).
- The entry check refuses a loop program without each of its four checks on what the host writes, a program that hands the host an array outside the heap, a host that leaves the heap header unwritten, and a server whose reply is wrong.
- The framing check has to see thirty-four defects planted in the printed framers: twenty that break a rule of the framing, planted in both programs of their kind, where the cases of each have to show them — but a byte kept or held past the buffer, which ends the process at the page without access after a state of 512 or 64 bytes and is caught by the check of the state's page at four — and fourteen for the host's own checks, planted at the size the session uses, each stopping the host with its own message or at a page without access (listed in `scripts/framing_check.py`).
- The session check has to see fifteen rules of the session broken in the model (`DN.News.SessionMutant`), each refused by the judge on some scenario, and fourteen defects planted in recorded traces, each by the check for it (listed in `scripts/session_check.py`). In Lean, seventeen versions of the reply rules, each with one broken, give another reply to a line written for it (`DN.News.CommandSpec.mutants_differ`).
- The grammar check has to see twenty-one defects planted in the reference's grammar text and five mutants of the interpreter, each as answers that differ ([details](#header-field-grammar)).
- The article check has to see twenty-four versions of the rules, each with one changed, answer some case otherwise than the reference ([details](#article-acceptance)).
- The journal check has to see thirteen versions of the rules of reading, each with one changed, answer some case otherwise than the reference ([details](#journal)).
- The file system check has to see every version of the model with one rule changed answer some case otherwise than the reference ([details](#file-system)).
- The runs check has to catch the store's program broken in each way it sets out, by drawn scenarios ([details](#store-runs)).
- The store check has to see every version of recovery with one rule changed answer some case otherwise than the reference ([details](#store)).
- The session program check has to catch thirty defects planted in the printed program, each the way it names ([details](#session-program)).
- The NNTP server check has to catch forty defects, thirty-four planted in its host and six in its program, each by the check named for it and for the reason named ([details](#nntp-server)).

The Lean build carries no warnings, and `--wfail` makes one fail the build; Lake replays a module's stored log, so this holds on a warm cache as well as on a fresh checkout. A warning-free log is a hygiene property, not a correctness argument. `autoImplicit` is off, so a mistyped name is an error instead of a silent new variable.

## Concrete findings fixed during baseline work

### Exported region bounds could overflow

The original guard compared `alen < off + len` using signed 64-bit words. For example, `off = 2^64 - 1` and `len = 1` wrap the sum to zero, allowing an invalid byte access. The former native tests exercised only small offsets and could not find it.

The exported function now rejects sign-bit-set sizes/offsets/lengths, requires `off <= alen`, and compares `len` with `alen - off`. Regressions exist in the executable Lean model and in the real native test with inaccessible memory. The historical FFI-oriented `emitRegion` example still has its original small-range caller assumptions; do not expose it as an unchecked native API.

### We assumed a 64-bit C return that the backend does not provide

The pinned x86-64 export trampoline uses `mov %edi, %eax` at `cake_return`. Our old C prototype claimed a 64-bit return. The existing digest fits in 24 bits and hid the problem; the new probe `0 + 2^32` returned zero to C despite computing the full word internally.

The native interfaces now declare a 32-bit result. `Abi.wordResult` rewrites value returns, including returns nested in control flow, to write a caller-owned word and return status zero. The model and native baseline check that transformation on all 119 fixture functions: 113 expression shapes, two control workloads and four nested loads. The echo kernel returns only a bounded length (0–4096) or `UINT32_MAX`. This is an explicit adaptation to the backend ABI, not an assembly patch or a claimed upstream compiler fix.

### The theorem-only audit missed isolated definitions

An unapproved axiom inside a `DN` definition could previously escape if no audited theorem depended on it. The audit is now a standalone program that imports every module under `lean/DN` and checks every declaration they define; negative gate tests exercise this case among others.

### Raw printing and lowering were not an emission contract

`lower` intentionally handles a restricted model and ignores function-level ABI details. `ppFun` is a printer, not a validator. `Checked.emit` checks scalar parameters, ASCII identifiers, keywords, unique names, local scope, word-sized literals, allowed effects, an exported name inside the `dn_` namespace, and an explicit final return before CLI emission. Each rule has its own refusal reason, and `Checked.catalog` carries a rejected/accepted pair per reason: a rule with no pair, or a pair refused by a different rule, fails the build. That an accepted function has a model image is proven (`Checked.accepted_lowers`), not checked at runtime. Unsupported shapes, calls, and FFI are rejected in this exported profile. It does not establish memory safety, pointer validity, or termination.

What the gate accepts, the compiler must accept silently: every accepted example of the catalog is compiled in the native lane and any diagnostic fails the build. The gate is not a copy of the compiler's own analyses, though. It does not reproduce the check that a store address is derived from a pointer the caller supplied, so a program storing through a literal address passes the gate and is then refused by the build for the compiler's warning rather than by the gate. Treat the diagnostics as the boundary of the profile, not the gate alone.

The keyword list is not written by hand: `scripts/gen_keywords.py` generates `DN.Compiler.Keywords` from `get_keyword_def` in the Pancake lexer of each pinned revision, the scheduled job regenerates it and fails on a difference, and the native lane checks the table against the compiler it actually runs — a word the table calls a keyword must be refused as a name, and a word it records only for the other revision must be accepted. Two details of the lexer matter to anyone writing `.pnk` by hand: `@base`, `@top` and `@biw` are keywords only with the `@` (and `@top` lexes to the same token as `@base`), and a leading digit in a declaration is read as a shape, so `var 1x = a;` silently declares `x`.

### Decimal rendering took time proportional to the number

The digit loop divided by ten by repeated subtraction, so rendering `m` cost about `m/10`
iterations: 238,609,298 of them for the largest article number RFC 3977 allows. Pancake has
no division and its multiplication yields only the low half of a product, so the quotient is
now built from two multiplications by `3435973837`, one per half of the word, with
`2^32 = 429496729 * 10 + 6` carrying the remainder between them (`DN.Compiler.Div10`). The
correspondence with division is proven for every machine word, and a separate theorem
states that no intermediate product overflows (`Div10.div10w_products_fit`), which is why
Pancake's truncating multiplication loses nothing here.

A digit now costs no clock at all — the model spends clock only in loops — so the render
spends one tick per digit after the first, and never more than nineteen for any machine
word (`NatToDec.natToDecProg_sem` with `renderFuel_le_nineteen`); two theorems run it on a
concrete state, for 404 and for zero. The same render is emitted as `dn_render` and run
natively against the C library's conversion. The model has the shape the emitter prints:
the working names are declared once, ahead of the loop, and assigned inside it, so the
emitted digit sequence lowers definitionally to the program the theorem runs
(`Kernels.render_body_lowering`, `Kernels.digit_loop_lowering`). What is still read rather
than proven is the rest of the emitted function — the saved start pointer and the returned
byte count — and the native host, as for the other kernels. The rendering specification and
its byte-level postcondition are the ones that were there before.

## Which parts are trustworthy enough to build on?

**Maintained native subset:** `Syntax`, `Lower`, `Checked`, `Abi`, `Kernels`, the source language in `DN.Dsl`, whose compilation is proven in the model for every program `emit` accepts, and the explicit paths in `Main`. Scalar 64-bit arithmetic uses modular add/subtract/multiply, bitwise AND, equality, and signed comparisons. Memory is supplied by the host. Whole-word results cross the C boundary through output slots. Start changes here and extend differential coverage with each new construct.

**Reusable model results:** `Semantics`, `Region`, `Clock`, `Bytes`, `ByteCopy`, `Certificate`, and the dataplane models. The emitted echo loop lowers definitionally to `ByteCopy.copyByteWhile`, the loop used by the existing copy proof. The wrapper/host/native path still needs a complete refinement argument. Clocks represent model fuel, not CPU time.

**Removed inherited workloads:** the `Stage*`, `Serve*`, serializer and structure-emitter modules were removed. Their certificates required premises that no model state satisfies, their "compiler" ignored the program it compiled, and their memory model put one byte in each machine word, which the CakeML compiler theorem never provides. The emitted code is unchanged, byte for byte; `tests/golden` now pins it. The extraction manifest records where they came from, and git history keeps them.

**Preserved source:** `migration/dataplane` is still a reference snapshot, and the source gate holds it to that: every file in it is recorded in the extraction manifest and still hashes to the bytes it arrived with, so a change there fails the checks instead of passing unnoticed. What a port has to redesign before reusing any of it is listed in [porting risks](porting-risks.md). The echo host is new, small, and uses `poll`; it does not activate the old io_uring/kqueue product or prove correspondence to the abstract concurrency models.
