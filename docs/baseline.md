# Compiler baseline

The maintained core is the emitted Pancake subset, its proofs, the dataplane models and the NNTP server built on them; the [four-reviewer audit](reviews/README.md) lists the inherited contracts and gaps to read before extending the preserved modules.

## Reproduce the baseline

On Linux x86-64, with the prerequisites of the root README:

```sh
bash scripts/check_all.sh
```

It fails if any lane fails and skips nothing on an unsupported host; `scripts/check.sh` is the baseline without the native lanes and `scripts/lint.sh` the static checks.

The native lanes are listed once, in `scripts/native_lanes.sh` (`bash scripts/native_lanes.sh parser` runs only the ones named). CI runs each on a machine of its own after lint and a build without network, beside the proofs, the tests' groups and LazyFS; `check_all.sh` runs three lanes or groups at a time (`DN_PARALLEL`).

Each lane writes `build/<lane>/report.json` with the platform, the digests of the compiler, `dn-compiler` and the host sources and its time, removes its last report before it starts, and says why it refuses in one line starting with `DN`.

A check that passed is not run again on the inputs it read (`scripts/once.py`): under strace it records each file it read, directory it listed and path it missed. Python's imports look up the names they search for, so a new module no import names runs nothing again. `DN_ONCE=off` runs all.

A run of git in the repository that only reads, in the same environment, counts by its answer; `dn-compiler` by the declarations its commands reach, their compiled code and how it starts (`scripts/Fingerprint.lean`). A skipped lane keeps the report of the run it stands for.

What the checks require of the documents is kept with their stamps and held by `scripts/check_documents.py`, so a change to the documents alone runs no check again.

In CI an artifact keyed by the job's inputs is seen across branches (`scripts/prior_pass.py`), so the run on `main` after a merge says `DN SKIP`; only runs of this repository's branches count, trusted as its writers are. The checks' stamps keep a pass in each of the last three runner environments and come from the branch's own runs or `main`'s.

Each linter is a check of its own, and each commit is read for secrets once. A pull request's next run waits for the one in progress instead of cancelling it. A nightly job whose inputs are the repository's alone runs once per key, on CI's build; advisories, the network's answers and new seeds run every night.

A writer who ran every check on a tree notes it on the commit (`refs/notes/checked`, `CHECKED` in `scripts/verify_run.py`), which only a writer can push. Each CI job then takes the note as a pass on its inputs and runs nothing again; `verify` still requires every job to pass. Each night `checks` runs on `main` by itself.

The note says what it was written after: `scripts/check_all.sh`, lint included with every commit after the default branch, `scripts/lazyfs_check.py` and `scripts/native_lanes.sh power`, each passed on the commit in an isolated container, the note then pushed with the branch.

A lint pass recorded by CI is keyed by the commit and by whether it read every commit or the new ones, as lint reads the history; a merge is read against its first parent.

`python3 scripts/native_fuzz.py --cake "$(python3 scripts/bootstrap_tool.py cake)" --seed N --count C --vectors V` runs the generated lane larger, as the nightly run does with 5,000 programs from a seed of the date, reducing a disagreement to `build/fuzz/minimized/`; `--bootstrapped` uses the compiler built from the patched source.

The default compiler is the release pinned in `tools.lock.json`, run with the simple register allocator (`--reg_alg=0`, [assurance](assurance.md)); `CAKE` selects another, whose digest is recorded, such as the one `scripts/bootstrap_cake.sh` builds ([backend](../backend/README.md#bootstrap-the-compiler)).

The LazyFS lane (`python3 scripts/lazyfs_check.py`, after `python3 scripts/bootstrap_tool.py lazyfs`) and the power lane (`bash scripts/native_lanes.sh power`) need `/dev/fuse`, libfuse 3 and the right to mount it, and run apart from `check_all.sh`; the power lane is not run again on a tree it passed on.

### Generated programs

`DN.Compiler.Gen` draws the programs by swarm testing, and on every call the model, `scripts/fuzz_interp.py` and the compiled code must return the same word and change the same memory, each buffer between pages without access.

A program may call two functions of its own, of up to three parameters: data and the pointer `p`. A run spends at most 10,000 steps of the model's clock, a call at most 600, and each block is built within its share.

### Printed source against the parser

`cake --explore` reads each program as its lowering in canonical form, helpers included, and the parser the precedence table as written, of which `printed_well` relies on 62; `--bootstrapped` checks the bootstrapped compiler too.

### Reply table

Each input is called with buffers of the exact room, more, one byte less and negative lengths, between pages without access, against the Lean program and an independent reference.

### Entry designs

`scripts/entry_bench.py check` holds every reply, the heap header the compiler theorem requires and hostile hosts, and four servers answer over loopback.

### Server loop

`scripts/server_check.py` runs the loop with a scripted host checking the heap header, the layout and every array on each call, and `SkeletonSafe.never_fails` proves no run fails for any host.

### Framers

`scripts/framing_check.py` holds `dn-compiler frame-model`, `scripts/framing_ref.py` and the compiled framers fed a chunk at a time, each chunk next to a page without access, every way through each program taken.

### Header field grammar

`scripts/gen_abnf.py` takes the grammar from the RFCs' ABNF with their verified errata; the terms a match goes through at one position are bounded, 36 for this grammar.

On 49,838 cases, among them 107 examples the RFCs print, the interpreter and the library agree, every example answered as the RFCs have it, those refused, 9 in all. Each of 21 defects planted in the reference's grammar and 5 mutants of the interpreter is caught.

### Header field grammar in Pancake

`DN.News.AbnfProg` makes a function of each rule but a byte class or a string, which it reads from a table. A function takes a set of positions to where its matches end, as the interpreter does; the comment's is a scan with a count of depth.

The analysis of decision 0004 accepts the program, and refuses it when its functions do not check their slots.

`scripts/grammar_check.py` holds the compiled program to `dn-compiler abnf-model` on 52,321 cases: the grammar lane's, 17 hostile fields of about 4 KiB, and 2,466 from several starts, answered as the input after each. It catches each of 7 mutants.

At 64 KiB the hostile fields are answered as at 4 KiB and take at most twice as long per octet; the host checks the heap on every call.

### Article acceptance

`dn-compiler article-model` and `scripts/article_ref.py` agree to the byte on 18,360 cases, including 25 of INN's test articles, 13 contexts past the bounds and 157,055 days of dates, and each of 24 versions of the rules with one changed is caught.

### Article acceptance in Pancake

`DN.News.ArticleProg` checks a proto-article over the grammar's functions as `ArticleSpec.checkWith` does, built from its rules: the header section's shape, each field, the article's rules, and what is added. Quotients come bit by bit from a table of powers of two. Wall clocks are taken below 2^40 seconds; a year of any length is read by its place in 400 years.

The analysis of decision 0004 accepts the program, and refuses it when a copy does not check where it reads.

`scripts/accept_check.py` holds the compiled program to `dn-compiler article-model` on 332,497 cases: the article lane's, its dates written and read back, long years, lone CRs and quoted parentheses. It catches each of 6 mutants.

The program refuses the 13 contexts past the bounds, one with an empty group and a wall clock of 2^40; its host refuses numbers no word holds.

At 64 KiB, 9 hard forms are answered as the model answers them, at most twice as slow per octet as at 4 KiB. The host checks the heap on every call.

### Journal

`dn-compiler journal-model` and `scripts/store_ref.py` agree on 15,931 cases, among them the 5 examples of RFC 7143 and 719 frames torn into parts. A changed byte stops reading on the tag for 1,430 of the 1,578, and each of 13 versions of the rules of reading is caught.

### File system

`dn-compiler fs-model` and `scripts/fs_ref.py` agree on 25,874 cases — 51 table cases, 1,500 runs drawn, 600 lives of one file, 7,474 images listed and 16,249 images changed — and each of 16 versions of the model is caught.

### Store

`dn-compiler recovery-model` and `scripts/recovery_ref.py` agree on 1,611 cases — 111 directories of the table, 600 directories drawn, 300 lists of actions, and again after the actions of the 731 that recover — and each of 25 versions of recovery is caught.

### Store runs

`scripts/runs_check.py` runs the store's program as `dn-compiler store-model` does over 120 chains of runs, 239 runs, 192 restarts and 55 starts failing. It holds 22,856 directories a crash may leave at 8,474 points to `store_safe`, refuses 1,787 events it may not make of 15 kinds of event, and catches the program broken in 11 ways.

### Fault points

`scripts/fiu_check.py` builds `native/fault_probe.c`, a point as the host writes them (`native/faults.h`), with `FIU_ENABLE` and without it or libfiu's headers, and checks its point fails only as enabled.

### LazyFS

`scripts/lazyfs_check.py` mounts LazyFS from its pins, clears its cache and tears an append, and a plain directory fails the same checks.

### Session model

`scripts/session_check.py` drives `dn-compiler session-model` with a simulated host through 402 scenarios and 3,310 turns, `scripts/session_ref.py` judging every turn and seventeen hosts that break the contract ending the run, five of them by an index opened at a generation not past its last or past 2^62.

Scenarios with a store post articles: at the bounds of size, header and capacity, five at once, one Message-ID twice, file operations failing, the store stopping with others in flight. They read them too: nine readers, four posts beside eight reads, files of 16,384 and 32,768 octets, files failing their checks or changed after the start, slow readers.

Others select groups and walk them: by number, NEXT and LAST over a hole, crossposts, an empty group, a read by number that fails. They try names malformed, every octet in one, UTF-8 at its edges, names of 64 and 65 octets, and groups as articles are posted to them.

Others list: LISTGROUP over ranges, with no group selected and of an empty group, LIST ACTIVE over wildmats at their edges and of every octet a word may hold, and malformed arguments of each listing, DATE and NEWGROUPS. DATE runs at fields of one digit, at the calendar's edges and past the year 9999.

200 articles go to a slow reader, in parts that fill an action to its last octet, as an article is posted to their group, and to a reader that pauses.

Forty groups go to a slow reader as the store stops, and the groups are listed once it has stopped; so are sixty-four, the most a store carries. A host comes 200 seconds late to each turn of a listing with a line begun behind it.

Others ask for READER: the capabilities and MODE READER of a client that may post, of one that may not, once the store has stopped and of a store with no group, MODE READER between GROUP and LISTGROUP, and MODE's arguments. Without a store MODE READER ends the connection.

Others ask for overview: OVER, HDR, XOVER and XHDR by message-id, by range and of the current article, with no group selected and of an empty group. Their fields come folded, twice, in lower case, with a TAB or absent, a header section of 69,632 octets and one past it.

Files fail their checks at the first article and at a later one, a big group goes to a slow reader, an OVER waits among eight reads, an article is posted to the group an OVER reads, and a reader resets during one.

Others change each letter of every keyword, with a store and without, put every octet at each place of a range and of an article's number, ask for commands a store does not have, and list groups whose numbers have one digit to three.

The host keeps the spool on `scripts/fs_ref.py`. `scripts/post_ref.py` checks headers by `scripts/article_ref.py`, holds every job to decision 0005's order, recovers crash images after each 240, and checks every file read against its own copy of the spool.

Each of the session's 131 rules broken in the model (`DN.News.SessionMutant`, 28 of them POST's, 13 reading's, 14 the selected group's, 23 the listings', 6 READER's and 32 those of OVER and HDR) is caught. So are 21 planted defects, each by the check named for it; thirteen hosts that report a completion they may not end the run.

### Session program

`scripts/session_native.py` requires the compiled session's trace, jobs included, to equal the model's on the model's 402 scenarios and 3,310 turns, on the other 145 with a store and 14,983 turns, and on 200 hosts drawn at random without one.

With a store the program first recovers it: from the spool the model's starts from, before its start record, and once from an empty directory.

It catches 103 planted defects, sixty-five in the store's side, the selected group's, the listings', READER's and the overview's. The analysis accepts the program in the pieces of `DN.Server.SessionCert`, the claims of its functions a run of them at a time.

### NNTP server

`scripts/nntp_check.py` runs the server over loopback, holds each run to `session_ref`, the model and the sockets, sends three transcripts cut at 1,831 cuts, and starts on every store directory of the store lane. Reader commands on a spool are cut between two reads at each of their octets. It catches 60 planted defects.

On the virtual clock an earlier deadline brings the program's wake forward and, cleared, gives it back to the earliest left; a clock set back, or at 2^62, ends the host with status 2.

It posts on an empty spool, after a restart and through `nntplib`, finds each poster in the host's log by `logging-data`, reads each article back through `nntplib`, walks their group by GROUP, NEXT, LAST and number, and refuses one whose file changed on the disk. It lists the group by LIST, LISTGROUP, DATE and NEWGROUPS.

`nntplib` reads the capabilities with READER. Asked for reader mode, it sends MODE READER to a server without a store, which answers 502 and closes the connection.

Perl's Net::NNTP 3.15, the version checked, is a client written apart from both. Connecting, it sends MODE READER and is told it may post. It posts two articles, one with lines that start with a dot.

It finds them by DATE, LIST, LIST ACTIVE, LIST NEWSGROUPS, NEWGROUPS of a two-digit year, GROUP, LISTGROUP, STAT, NEXT, LAST and ARTICLE. Without a store its MODE READER gets 502 and the connection closes. Each line Net::NNTP sends and each status line it reads is held, and so is what it makes of them.

Its settings come from a file too: `--check-config` writes them as JSON, and an unknown setting, one without a value or one given twice refuses the start, naming the line. Started with a socket from systemd it listens there. SIGUSR1 and the stop write its counters, held against what two clients sent and were sent.

Installed alone in a directory, it is started, restarted, its spool copied and the copy served with every article; a copy's journal torn in its last commit is cut at the start, the articles before it served ([runbook](runbook.md)).

slrn 1.0.3, a newsreader written apart from the server, enters a group of a thread of three, each of its own Subject, and an article alone. It asks XOVER, threads the articles by References, takes a folded Subject from the overview unfolded and reads the first article. Each command it sends and the first line of its answer are held.

### Crashes

`scripts/crash_check.py` kills the server's test build before each of its 27, 39 and 44 operations. It posts two articles at once into overlapping groups on an empty spool; then one Message-ID from two connections at once, one held already, a crosspost and a read; then one article on a spool a crash left, stopping recovery too.

Each spool left is held to `store_safe` by `scripts/recovery_ref.py`, with every article it held before; each client read what a run not stopped sends, or its start. Started again, the server recovers alike, reads every article back through `nntplib`, takes a new one numbered on and refuses one held. It catches 5 planted defects of the crash lane.

### Power loss

`scripts/power_check.py` runs the crash lane's phases on LazyFS, which caches unsynced data. Power is lost before each of the 27, 39 and 44 operations; after a run with each failed with EIO; and in each of 4, 3 and 3 writes to the journal and a kept tail, torn in three, first, last or both parts kept.

Each spool is held as in the crash lane; where an operation failed, a post may be refused or one closed unanswered, and an article refused is never found. Started again, the server removes a mark of another boot. It catches 4 planted defects of the power lane.

### Faults

`scripts/faults_check.py` runs the crash lane's server on a spool holding an article, and on that spool as a crash leaves it: a post, ARTICLE of the article held, another post, STAT, the capabilities and LIST ACTIVE, one client after another. POST leaves the capabilities and LIST ACTIVE says `n` once the store stops.

Each of its 35 and 46 operations at a point fails once with ENOSPC, every reply as decision 0005 has it for the point and the file. An article's creation, write or rename refuses the post; its sync also stops the store and leaves the mark.

The journal's write or sync leaves the post unanswered and stops the store; a read's failure answers 403. Each operation is also interrupted once with EINTR, and where the host makes the call again the run is as without it. The stop's counters count the one file job that failed, of its class.

Every write cut to one octet changes nothing; a write of no progress refuses the start. With every sync slowed, a read and a STAT on other connections are answered before a post's 240, which waits for its three syncs.

With each index's generations counted up to the last but one as a connection opens there, every client opens at an index's last generation and the next at another, and the run is as without it.

SIGTERM as each operation of the run begins stops the server with status 0 once the job running it has run out, none left running; the spool is held as after a crash, and started again the server serves it.

With every index taken at once a 65th connection waits for one to close. Eight slow reads of the large article through small buffers, the server holding what they have not taken, one reset midway, eight posts with every sync slowed and HELP on the rest are all answered.

No file of the spool is left open; the allocator holds no more once the server serves, and at most 6 MiB more is resident than at start. A poll that fails ends the host with status 2.

Each spool is held as in the crash lane. It catches 11 planted defects of the faults lane.

An article's file changed after the start in 6 ways after `fn`'s table, of one buffer and of two, is never sent whole; STAT still answers and a post is taken. The next start refuses the store where recovery finds it corrupt or a file opens no more.

### Host's store

`scripts/host_check.py` runs the host with `native/host_driver.c` for the program, through spools, the log of connections, file jobs, libfiu points and Helgrind, and catches each defect planted in it.

### Test sensitivity

Each lane catches its planted defects, from copy and reply kernels to the session's program and sixty NNTP servers (forty planted in its host and twenty in its program).

The Lean build carries no warnings (`--wfail`) and `autoImplicit` is off.

## Fixed during baseline work

- Region bounds overflowed in a signed guard; the export now rejects sign-bit sizes and compares `len` with `alen - off`.
- The backend returns 32 bits to C; `Abi.wordResult` writes results to a caller-owned word, checked on all 189 fixture functions; in the model a run that does not fail ends the same rewritten, the slot in the memory domain (`DN.Compiler.Preservation`).
- The audit missed isolated definitions; it now checks every declaration of every module.
- Printing was no emission contract; `Checked.emit` refuses each unsupported shape for its own reason, and the native lane compiles every accepted example silently.
- Decimal rendering took time proportional to the number; `DN.Compiler.Div10` divides by multiplication, proven for every word.

## What to build on

The emitted subset (`Syntax`, `Lower`, `Checked`, `Abi`, `Kernels`, `DN.Dsl`) and the model results (`Semantics`, `Region`, `ByteCopy`, the dataplane models) are maintained; `migration/dataplane` is a hash-pinned reference snapshot ([porting risks](porting-risks.md)).

The honest claim: **this subset builds, refuses known unsupported inputs, agrees with independent references on the recorded suite and drives a tested NNTP server.**
